# QuoteResponse ユーザー登録フロー設計

## テーブル構造分析

### Users テーブル（必須情報）

- `email` - 招待メール時に確定
- `password` - 登録時に必須
- `status` - pending → active（管理者承認後）

### Companies テーブル（段階的登録）

**第一段階（登録時）**:

- `name` - 会社名（必須）
- `company_type` - 個人/法人（必須、デフォルト: individual）

**第二段階（ダッシュボード）**:

- `legal_name` - 法人正式名称
- `registration_number` - 法人番号
- `phone`, `email` - 連絡先
- `representative_name`, `representative_title` - 代表者情報

### Profiles テーブル（ユーザー個人情報）

**第二段階（ダッシュボード）**:

- `last_name`, `first_name` - 氏名
- `last_name_kana`, `first_name_kana` - 氏名（カナ）
- `phone`, `mobile` - 電話番号

### Addresses テーブル（会社住所）

**第二段階（ダッシュボード）**:

- `postal_code`, `prefecture`, `city`, `address_other` - 住所情報
- `phone` - 住所の電話番号
- `is_default` - デフォルト住所

---

## 推奨フロー：2段階登録 + ダッシュボード進捗管理

### 理由

1. **登録時のストレス最小化**: 最小限の情報のみで登録完了
2. **エラー低減**: テーブル間の複雑な関連付けを避ける
3. **フレキシビリティ**: ログイン後、段階的に情報追加可能
4. **契約書準備**: 必要な情報が揃ったタイミングで作成

## 実装上の重要な注意点

### 1. エラーハンドリング

- 各登録段階を独立させることで、1つのテーブル操作失敗がユーザー作成を妨げない
- トランザクション: 第一段階のみ（User, Company作成）
- 第二段階: 各段階で独立したトランザクション

### 2. 登録状態の追跡

`users.status` の遷移:

```
pending → active (管理者承認)
```

新しいカラムの追加も検討:

```
Schema::table('users', function (Blueprint $table) {
    $table->json('registration_status')->default(json_encode([
        'profile' => false,
        'company_info' => false,
        'company_address' => false
    ]));
});
```

### 3. ダッシュボード進捗表示

```php
// 登録状況をチェック
$registrationStatus = [
    'profile' => $user->profile()->exists(),
    'company_info' => $user->companies()->where('id', $company->id)
        ->where(function($q) {
            $q->whereNotNull('legal_name')
              ->whereNotNull('phone');
        })->exists(),
    'company_address' => $company->addresses()->where('is_default', true)->exists()
];

$allComplete = !in_array(false, $registrationStatus);
```
